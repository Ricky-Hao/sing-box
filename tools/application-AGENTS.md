# Generated sing-box application

This is an immutable application snapshot generated by the maintenance repository's
`manifest.json` and five feature patches. `main` owns maintenance; `rickyhao/stable`
is the preserved legacy fork. Keep module `github.com/sagernet/sing-box`.

Read the maintenance checkout's `README.md`, `MAINTENANCE.md`, `AGENTS.md`, and the
affected `patches/<id>/README.md` before editing. Never edit this version branch in
place: create an `edit/<feature>` branch/worktree, then write every source change
back to its owning patch against the exact preceding tree. Generate a fresh
`vX.Y.Z-patchset-N` snapshot; never reset, clean, stash, force-update, or overwrite
an existing snapshot or another worktree.

Each group delivers one complete feature or independent fix, including necessary
callers, build wiring, existing tests, configuration/schema and use documentation.
Fold historical corrections into that group. Split only when an ability can be
applied, verified and retired independently. File count, layers and historical
commit count are not split criteria. Shared files have one owner per hunk; record
real dependencies only. CI, release matrices, signing and Devcontainer belong to
maintenance main, not an extra business patch. Do not change unrelated upstream
behavior or WireGuard while maintaining iWAN.

## iWAN and Android

- Build iWAN with both `with_iwan` and `with_gvisor`. Preserve CLI release tag files,
  mobile `cmd/internal/build_libbox/main.go`, and include/stub registration.
- iWAN uses the userspace stack only; `system: true` is unsupported. `address` is
  optional and OPENACK provides the effective IPv4 address. `allowed_ips` only
  influences `preferred_by`; it installs no OS routes.
- Keep OPEN/OPENACK/OPENREJ/DATA/DATA_ENC/ECHO/CLOSE, IPFRAG, MD5 control signatures,
  AES-128 password TLV block, XOR data encryption, tokens/sessions and TLV lengths
  compatible with iwand. MD5/XOR are legacy protocol limitations; no new claims of
  modern transport security. Use connected UDP or explicit source validation.
- Segment routing, OS routes, up/down scripts and applying OPENACK DNS to the
  system resolver remain out of scope.
- SFA must include iWAN/gVisor in mobile libbox; check that entry first for missing
  inclusion. Android logs must show transport/iwan and protocol/iwan.
- On mobile 5G start with MTU 1280, then try 1320/1360; do not default to 1420.
  Match `tun.mtu` when a TUN inbound is used.
- Release signing requires `SFA_RELEASE_KEYSTORE`, `SFA_KEYSTORE_PASS`,
  `SFA_KEY_ALIAS`, `SFA_KEY_PASS`. Never generate temporary release keys or commit
  keystores, credentials, decoded secrets, debug configs or secret-bearing logs.

## Validation and actions

Run from this generated application's root, not maintenance main:

```sh
go test -tags with_iwan,with_gvisor ./transport/iwan ./protocol/iwan ./option
go test -tags with_iwan,with_gvisor ./include
go test -run '^$' ./cmd/internal/build_libbox
go test -race ./common/urltest ./protocol/group ./route ./dns ./protocol/dns
```

Run gofmt on changed Go files and `git diff --check` on actual application changes.
Use group contracts in maintenance `patches/*/tests.json` and project checks in
maintenance CI. Preserve original business regressions. Root `Makefile` is upstream
source; its release/publish/update targets are not maintenance entry points.

Release outputs: arm64-v8a SFA APK and linux/windows/darwin/freebsd amd64/arm64 CLI
archives; Linux pure Go and musl only. No glibc, SFM, deb or OpenWrt assets.
Upstream workflows are inactive archives in `.github/upstream-workflows/`.
Only maintenance CI rebuilds and releases after a merged main revision passes.

Do not commit, push, tag, publish, dispatch CI, deploy or use real devices without
explicit authorization. Real smoke tests use disposable configs without committed
credentials. Local/static checks do not claim a remote build or published asset
verification; report any unperformed Android/device/remote validation precisely.
